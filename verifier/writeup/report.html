The Jumping Pad: an agent-coding eval built on a real 3D game

We ablated one feature — a mushroom launch pad — from RoboBlast, a real third-person shooter. We built a 100-point headless verifier for it, stress-tested that verifier against 8 near-miss implementations, then ran 18 real rollouts across 6 agent/harness configurations to see how they'd actually do.

01Why this feature

Somewhere in the level sits a small mushroom pad. Step on it, and it launches the player into the air with a satisfying, springy bounce - the cap squashing down on contact, then snapping back with an elastic overshoot before settling. We chose to ablate this behavior and hand it to agents to rebuild from a description alone.

It's the right size for the job. Big enough to have implementation complexity — a physics launch with its own magnitude, direction, and momentum rules, paired with a set of different visual animations — but not so big that it sprawls across the codebase.

02How difficulty was calibrated

The first spec draft stated the launch multiplier explicitly ("~3.4× a normal jump") and described the override mechanics in rough mathematical terms. On our early test rollouts, models we tested swept the verifier, scoring 100/100 by transcribing the spec's own numbers straight back into code — visible directly in their own comments.

G
"To reach 3.4x the normal jump height, we need sqrt(3.4) times the impulse." — Gemini 3 Flash, first rollout

We knew right away we needed to raise the difficulty. A model that only has to transcribe a spec's own numbers back into code isn't demonstrating any real understanding of the game — it's demonstrating that it can read.

We rewrote every mathematical and implementation detail into completely player-facing language. Numbers like "3.4×" and descriptions of override mechanics became descriptions of what the player actually experiences — "a dramatic super-bounce," "the pad sends them to the same result every time." That shift alone raised the bar: with no number to copy, an agent had to form its own judgment about what "dramatic" means, then verify that judgment against the running game rather than guess once and move on. Most, it turned out, never bothered with the second part.

We also sharpened the grading scale to match. Rather than accepting anything inside a generous band as fully correct, we rebuilt the verifier to hand out full marks only for close matches to the original's actual measured behavior, with every other outcome earning partial credit that shrinks the further it drifts — so a rough approximation and a precise one no longer score the same.

Result: 18 real rollouts, zero sweeps, zero cratering, every agent landing 79.6–98.4. That's exactly the calibration we were aiming for, and it held consistently across 6 very different agents — not a fluke on one model.

03The verifier

16 checks add up to 100 points, run headless against the game's real systems — real physics, real collision, whatever animation mechanism the agent actually used. Most checks score continuously, closer to the original earns more; a handful stay strictly binary, where the thing being tested is a yes-or-no property rather than a matter of degree.

Eight hand-written near-miss implementations, each built to fool a sloppy grader.

Every probe is a deliberate, hand-written near-miss — built by thinking adversarially about exactly what a sloppy grader would miss: right shape but faked physics, right physics but no visual polish, correct everywhere except one filter check.

05Evaluation integrity

Isolation

Every rollout gets a git archive export of the ablation branch into a fresh directory with a fresh git init — no history, no remotes, no other branches. This meant no verifier/ directory present, zero registered remotes, and the pad script confirmed ablated with no path back to the original anywhere on disk.

Network posture

Every harness we ran — Claude Code, Gemini CLI, and OpenCode — has an explicit deny-list blocking WebFetch, WebSearch, and any network-capable shell command, verified directly against each config. We also scanned every transcript for network-related tool calls after the fact: zero across all 18 rollouts.

Every attempt's diff is also scanned post-hoc for verbatim line matches against the original 16-line implementation. Across all 18 real rollouts, matches never exceeded 1 (the "plausible convergence" band for generic lines like var tween := create_tween()) and no run showed evidence of having seen the original source.

07Failure analysis

The headline finding: models converge on the same wrong number

Every guessed launch-magnitude ratio across all 18 runs, plotted against the scoring curve (shaded). Dots stack where multiple runs landed on the identical value.

10 of 18 runs converged on just two exact values — 6.41x (7 runs, spanning Claude Opus 4.8, Gemini 3 Flash, and both Gemini 3.1 Pro harnesses) and 8.75x (3 runs, spanning Gemini 3 Flash, Gemini 3.1 Pro native, and Gemini 3.1 Pro via OpenCode). Both back-calculate to respective launch velocities of ~30 m/s and ~35 m/s while the original's actual value is 22 m/s (~3.43x the regular jump height).

This is not a verifier artifact. Critical values like jump_initial_impulse := 12.0 and gravity := -30.0 sat unhidden near the top of player.gd, a file every agent should have read. The pad's own tuning constant was deleted with the rest of the ablated script so closing that gap meant testing a guess in-engine against a normal jump. With the Godot MCP available for exactly that, none of 18 rollouts did. Different models, providers, and harnesses converging on the same two round numbers points to a shared "big jump" training convention, not task-specific reasoning.

A genuine judgment call, not a clean miss

gemini3flash-2 (our one outlier, 79.6) lost all 15 T7 points because its hand-crafted 4-step squash sequence stretched to 160% of rest size — landing exactly on the curve's upper zero-cutoff.

08How to navigate this fork

main — locked base, untouched original game
task/jumppad-ablation — what the agent sees: ablated pad + SPEC.md
verifier — verify.gd, README, this writeup, all 8 probes + evidence
runs/<agent>-<n> — each rollout's diff + transcript + telltale scan + grade report (18 branches)

Verifier lives only on verifier, never merged into the ablation branch or main — the rollout agent's exported snapshot has no path to reach it, proven directly in section 05. To grade an attempt yourself, run:

/Applications/Godot.app/Contents/MacOS/Godot --headless \
  --path <project-under-test> \
  --script res://verifier/verify.gd

09Conclusion

The verifier holds up: every probe fails honestly, every real agent scores on a continuous curve, and the one biggest gap in the task — the pad's own launch magnitude — separates every model tested from a perfect score.
